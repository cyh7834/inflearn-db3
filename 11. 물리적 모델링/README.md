# 11. 물리적 모델링

## 1. 물리적 모델링 개요

- **목적**: 실제 시스템의 성능, 저장 공간 효율성, 유지보수 편의성 등을 극대화함.
- **논리적 모델링과의 차이**: 논리적 모델링이 데이터의 논리적 무결성과 관계에 중점을 둔다면, 물리적 모델링은 이를 바탕으로 실제 구현에 필요한 세부 사항을 추가하고 최적화함.

## 2. 테이블 및 컬럼 변환 규칙

### 기본 규칙

1.  **테이블/컬럼 변환**: 논리적 모델의 한글 이름을 영문 이름으로 변환하고, 명명 규칙(Naming Convention)을 따름.
    -   **명명 규칙**: 영어 사용, 소문자 스네이크 케이스, 명확하고 서술적인 이름 사용, 예약어 사용 금지, 일관성 있는 접두사/접미사 사용 권장.
    -   **PK**: '테이블명_id' 형식으로 명명함. (예: `member_id`)
    -   **FK**: 참조하는 테이블의 PK 이름을 그대로 사용함.
    -   **날짜/시간 컬럼**: 용도에 따라 `_at`, `_dt`, `_date` 접미사 사용.
    -   **불리언 타입**: `is_` 또는 `has_` 접두사 사용.
2.  **컬럼은 단수 명사 사용**: 테이블의 한 행이 가지는 단일 속성을 나타내므로 단수형 사용.
3.  **의미 있는 축약어**: 보편적이고 모호하지 않은 축약어(예: `id`, `qty`)는 사용 권장.

### 축약어와 단수 복수

-   **축약어 사용 지양**: 의미가 불분명한 축약어는 유지보수 비용을 증가시키므로, 명확성을 위해 전체 단어 사용 원칙.
-   **좋은 축약어 조건**: 보편성(Universality), 비모호성(Unambiguity), 일관성 및 문서화.
-   **테이블 이름**: 단수형(엔티티의 틀) 또는 복수형(데이터의 집합) 중 하나를 선택하여 프로젝트 내에서 일관성 유지. 한국 개발 환경에서는 단수형을 선호하는 경향이 있음.

## 3. 데이터 타입 선정

-   **중요성**: 잘못된 데이터 타입 선택은 저장 공간 낭비, 성능 저하, 데이터 무결성 훼손으로 이어짐.

-   **문자열 타입**:
    -   `VARCHAR(M)`: 가변 길이 문자열. 공간 효율성이 좋고 대부분의 문자열 데이터에 사용. 길이 설정 시 평균 및 최대 길이를 고려하여 합리적으로 설정.
    -   `CHAR(M)`: 고정 길이 문자열. 데이터 처리 속도는 빠르나 공간 낭비 가능성 있음. 주민등록번호, 전화번호 등 길이가 고정된 데이터에 사용.
    -   `TEXT`: 매우 긴 텍스트 데이터에 사용.

-   **숫자 타입**:
    -   `DECIMAL(M, D)`: 고정 소수점 타입. 금융 계산처럼 정확한 계산이 필요한 경우 사용.
    -   `DOUBLE` 또는 `FLOAT`: 부동 소수점 타입. 과학 계산이나 근사치가 허용되는 빠른 계산에 사용. 돈과 관련된 계산에는 사용 금지.
    -   `TINYINT`, `SMALLINT`, `MEDIUMINT`, `INT`, `BIGINT`: 정수형 타입. 저장 범위에 따라 선택.

-   **PK 타입 (INT vs BIGINT)**:
    -   **과거**: `INT`가 표준으로 사용되었으나, 현대 웹 서비스의 데이터 증가 속도를 고려하면 부족.
    -   **`BIGINT`의 장점**: 미래 확장성(예측 실패 방지), 외래키 관리 단순화, 고민 제거 및 개발 생산성 향상.
    -   **`BIGINT`의 단점**: `INT`보다 2배의 저장 공간 사용, 이론적으로 미미한 성능 차이. (현대 스토리지 환경에서는 큰 차이 없음)
    -   **실무 권장**: 핵심 테이블의 PK는 `BIGINT` 사용을 권장하여 장기적인 안정성과 유지보수 편의성 확보. 모든 PK를 `BIGINT`로 통일하는 전략도 선호됨.

-   **날짜 및 시간 타입**:
    -   `DATE`: 날짜만 저장.
    -   `DATETIME`: 날짜와 시간을 함께 저장. (실무에서 대부분 사용)
    -   `TIME`: 시간만 저장.
    -   **자동화**: `created_at`, `updated_at` 컬럼을 추가하고 `DEFAULT CURRENT_TIMESTAMP`, `ON UPDATE CURRENT_TIMESTAMP` 옵션을 사용해 데이터베이스가 자동으로 생성 및 수정 시간을 관리하도록 함.
