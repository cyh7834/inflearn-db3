# 11. 물리적 모델링

## 1. 물리적 모델링 개요

- **목적**: 실제 시스템의 성능, 저장 공간 효율성, 유지보수 편의성 등을 극대화함.
- **논리적 모델링과의 차이**: 논리적 모델링이 데이터의 논리적 무결성과 관계에 중점을 둔다면, 물리적 모델링은 이를 바탕으로 실제 구현에 필요한 세부 사항을 추가하고 최적화함.

## 2. 테이블 및 컬럼 변환 규칙

### 기본 규칙

1.  **테이블/컬럼 변환**: 논리적 모델의 한글 이름을 영문 이름으로 변환하고, 명명 규칙(Naming Convention)을 따름.
    -   **명명 규칙**: 영어 사용, 소문자 스네이크 케이스, 명확하고 서술적인 이름 사용, 예약어 사용 금지, 일관성 있는 접두사/접미사 사용 권장.
    -   **PK**: '테이블명_id' 형식으로 명명함. (예: `member_id`)
    -   **FK**: 참조하는 테이블의 PK 이름을 그대로 사용함.
    -   **날짜/시간 컬럼**: 용도에 따라 `_at`, `_dt`, `_date` 접미사 사용.
    -   **불리언 타입**: `is_` 또는 `has_` 접두사 사용.
2.  **컬럼은 단수 명사 사용**: 테이블의 한 행이 가지는 단일 속성을 나타내므로 단수형 사용.
3.  **의미 있는 축약어**: 보편적이고 모호하지 않은 축약어(예: `id`, `qty`)는 사용 권장.
