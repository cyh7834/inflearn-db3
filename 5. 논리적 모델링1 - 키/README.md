# 5. 논리적 모델링1 - 키

## 1. 데이터베이스 설계 3단계

1.  **개념적 모델링 (Conceptual Modeling)**: 비즈니스 요구사항을 ERD(Entity-Relationship Diagram)로 표현하여 데이터의 큰 그림을 그리는 단계.

2.  **논리적 모델링 (Logical Modeling)**: 개념적 모델을 관계형 데이터베이스 구조에 맞게 변환하는 단계.<br>
엔티티는 테이블로, 속성은 컬럼으로 변환하며 기본 키(Primary Key)와 외래 키(Foreign Key)를 정의. 이 단계는 특정 DBMS에 종속되지 않음.

3.  **물리적 모델링 (Physical Modeling)**: 논리적 모델을 실제 사용할 DBMS(예: MySQL)에 최적화하여 구현하는 단계. 데이터 타입, 인덱스 등을 결정.

## 2. 키(Key)의 종류와 역할

키는 테이블의 각 행(Row)을 고유하게 식별하고, 테이블 간의 관계를 맺으며, 데이터 무결성을 보장하는 핵심 장치.

-   **기본 키 (Primary Key - PK)**:
    -   테이블의 모든 행을 고유하게 식별하는 대표 키.
    -   `NOT NULL`, `UNIQUE`, `불변성(Immutable)`의 3가지 규칙을 반드시 지켜야 함.
-   **후보 키 (Candidate Key)**:
    -   기본 키가 될 수 있는 모든 키들의 집합.
    -   유일성(Unique)과 최소성(Minimality)을 모두 만족해야 함.
-   **대체 키 (Alternate Key)**:
    -   후보 키 중에서 기본 키로 선택되지 않은 나머지 키.
-   **외래 키 (Foreign Key - FK)**:
    -   한 테이블의 컬럼이 다른 테이블의 기본 키를 참조하여 테이블 간의 관계를 연결하는 역할.
    -   참조 무결성을 보장하는 중요한 역할.
-   **복합 키 (Composite Key)**:
    -   두 개 이상의 컬럼을 묶어서 하나의 기본 키로 사용하는 것.

    ## 3. 자연 키(Natural Key) vs 대리 키(Surrogate Key)

-   **자연 키 (Natural Key)**:
    -   비즈니스 로직 안에서 자연스럽게 발생하는 의미 있는 데이터(예: 이메일, 주민등록번호)를 기본 키로 사용하는 것.
    -   **장점**: 직관적이고, 비즈니스 규칙상 중복을 방지할 수 있음.
    -   **치명적 단점**: **변경 가능성**. 기본 키는 절대 변하면 안 되지만, 비즈니스 데이터(예: 이메일 변경)는 변경될 수 있다.<br>
    자연 키가 변경되면 참조 무결성 위반, 연쇄 업데이트로 인한 시스템 부하, 데이터 역사성 훼손, 외부 시스템 연동 문제 등 심각한 문제를 야기.

-   **대리 키 (Surrogate Key)**:
    -   비즈니스 로직과 무관하게, 오직 데이터 식별을 위해 시스템이 자동으로 생성하는 값(예: AUTO_INCREMENT 정수, UUID)을 기본 키로 사용하는 것.
    -   **장점**: **불변성(Immutable)**. 비즈니스 로직이 어떻게 변하든 대리 키는 절대 변하지 않아 데이터 모델의 안정성을 보장. 이로 인해 데이터 수정이 용이하고, 시스템이 유연해짐.
    -   **단점**: 추가적인 JOIN이 발생할 수 있고, 자연 키의 고유성 보장을 위해 별도의 UNIQUE 제약조건이 필요.


## 4. 현대 데이터베이스 설계의 표준 패턴

> **대리 키-PK, 자연 키-UNIQUE**

-   **기본 키(PK)**는 **대리 키(Surrogate Key)**를 사용.
    -   역할: 다른 테이블과의 관계를 맺는 '연결고리' 역할에만 집중.
    -   구현: `AUTO_INCREMENT` 숫자나 `UUID`를 사용.
-   **자연 키(Natural Key)**는 **UNIQUE 제약조건**으로 설정합니다.
    -   역할: 비즈니스 로직 상 데이터의 '고유성'을 보장하는 역할을 담당.
    -   구현: `email`, `login_id` 등 비즈니스 의미가 있는 컬럼에 `UNIQUE` 제약조건을 적용.

이 패턴은 **관계의 안정성**, **데이터 무결성**, **조회 성능**을 모두 만족시키는 사실상의 표준 방식. 역할의 분리를 통해 유연하고 안정적인 설계를 만든다.

## 5. 복합키와 다대다(N:M) 관계

-   **복합 키**: 두 개 이상의 컬럼을 조합하여 기본 키로 사용하는 것으로, 주로 다대다 관계를 해소하는 연결 테이블에서 사용.
-   **다대다 관계**: 두 테이블이 서로에게 1:N 관계를 맺는 경우로, 직접 표현이 불가능하여 중간에 **연결 테이블(Junction Table)**을 만들어 두 개의 1:N 관계로 풀어냄.
-   **연결 테이블의 키 설계**:
    1.  **전통적 방식**: 두 테이블의 외래 키를 묶어 복합 기본 키로 사용.
    2.  **현대적/권장 방식**:
        -   연결 테이블 자체의 **대리 키**를 **기본 키(PK)**로 사용.
        -   두 테이블의 외래 키 조합에는 **복합 UNIQUE 제약조건**을 설정하여 데이터 무결성을 보장.

이 방식은 복합키의 단점(뚱뚱한 키, ORM 사용 불편 등)을 해결하고 대리 키의 장점(단순성, 불변성, 확장성)을 취할 수 있어 실무에서 강력히 권장.
