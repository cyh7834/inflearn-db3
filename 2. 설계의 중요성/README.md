# 2. 설계의 중요성 --- 요약

## 1. 데이터베이스 설계의 첫걸음

-   데이터베이스 설계는 시스템의 뼈대를 만드는 과정으로, 집을 짓기 전
    설계도와 같다.
-   설계 없이 즉흥적으로 DB를 만들면 개발 초기에는 편해 보이지만,
    서비스가 커질수록 데이터 중복, 성능 저하, 유지보수 어려움이
    누적된다.
-   좋은 설계는 향후 발생할 문제를 예방하는 투자이며, 비즈니스 변화에
    유연하게 대응할 수 있는 기반이 된다.

## 2. 잘못된 설계가 부르는 재앙

### 2-1. 데이터 무결성 훼손

-   수정 이상(Update Anomaly): 여러 데이터 수정 누락 시 불일치 발생.
-   삽입 이상(Insertion Anomaly): 관계없는 정보 없이 원하는 정보를 넣을
    수 없는 모순.
-   삭제 이상(Deletion Anomaly): 필요 데이터 삭제 시 의도치 않은 중요
    정보 소실.

### 2-2. 성능 저하

-   고객, 상품, 주문이 한 테이블에 쌓여 테이블이 비대해지고 조회 성능
    저하.

### 2-3. 유지보수 비용 증가

-   작은 변경도 전체 스키마 수정 필요.
-   애플리케이션에서 DB 문제를 보완하느라 로직 복잡해짐.

## 3. 설계의 3단계 --- 개념, 논리, 물리

### 3-1. 개념적 설계 (Conceptual Design)

-   비즈니스 요구 기반 핵심 엔티티/관계 파악.
-   산출물: ERD.

### 3-2. 논리적 설계 (Logical Design)

-   정규화, PK/FK 정의 등 관계형 DB 이론 기반 구조화.
-   특정 DBMS에 종속되지 않는 스키마 생성.

### 3-3. 물리적 설계 (Physical Design)

-   실제 DBMS에 맞게 데이터 타입, 인덱스 등 최적화.
-   산출물: CREATE TABLE 스크립트.

## 4. 용어 정리

| 관점       | 구조 단위            | 항목 단위         | 데이터 단위       |
|------------|----------------------|--------------------|--------------------|
| 개념 모델  | 엔티티(Entity)       | 속성(Attribute)    | 인스턴스(Instance) |
| 논리 모델  | 릴레이션(Relation)   | 속성(Attribute)    | 튜플(Tuple)        |
| 물리 모델  | 테이블(Table)        | 컬럼(Column)       | 행(Row)            |

## 5. 정리

-   DB 설계는 개념 → 논리 → 물리 단계로 진행해야 한다.
-   잘못된 설계는 무결성 저하, 성능 문제, 유지보수 비용 증가를 초래한다.
-   좋은 설계는 장기적 안정성과 확장성을 보장하는 핵심 요소이다.
