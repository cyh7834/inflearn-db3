# 9. 논리적 모델링 - 실습

## 1. 개념에서 논리로: 변환의 법칙

개념적 모델의 추상적 요소를 논리적 모델의 구체적인 요소로 변환하는 명확한 규칙이 존재함.

-   **엔티티(Entity) → 테이블(Table)**: 데이터의 묶음인 '회원', '상품', '주문' 등의 엔티티는 실제 데이터가 저장되는 테이블로 변환됨.
-   **속성(Attribute) → 컬럼(Column)**: 각 엔티티의 세부 정보인 속성은 테이블의 컬럼으로 변환되며, 이 과정에서 `VARCHAR`, `BIGINT` 같은 구체적인 데이터 타입과 `NOT NULL` 등의 제약조건이 결정됨.
-   **식별자(Identifier) → 기본 키(Primary Key)**: 각 엔티티를 유일하게 구분하던 식별자는 테이블의 각 행(row)을 유일하게 보장하는 기본 키(PK)가 됨. 이 때, 비즈니스와 무관한 **대리 키(Surrogate Key)** 사용을 원칙으로 함. (예: `회원id BIGINT AUTO_INCREMENT`)
-   **관계(Relationship) → 외래 키(Foreign Key) + 제약조건**:
    -   **일대다(1:N)**: '다(N)' 쪽 테이블이 '일(1)' 쪽 테이블의 PK를 외래 키(FK)로 가짐. (예: `주문` 테이블에 `회원id` FK 추가)
    -   **일대일(1:1)**: 두 테이블 중 하나(주로 부가적이거나 나중에 생성되는 쪽)가 상대방의 PK를 FK로 가지며, 이 FK에 `UNIQUE` 제약조건을 추가함. (예: `배송` 테이블에 `주문id` FK UQ 추가)
    -   **다대다(M:N)**: 관계 자체가 새로운 **연결 테이블(Junction Table)**로 변환됨. 이 테이블은 양쪽 테이블의 PK를 모두 FK로 가짐. (예: `주문-상품` 관계가 `주문_항목` 테이블로 변환됨)
