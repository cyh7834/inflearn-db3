# 13. 다음으로

## 1. 강의 요약 및 복습

강의는 데이터베이스 설계 과정을 개념적 모델링부터 물리적 모델링까지 체계적으로 다룸.
-   **개념적 모델링**: 요구사항 분석, 엔티티/속성/식별자 식별, 관계(카디널리티, 참여도) 정의, ERD 작성.
-   **논리적 모델링**: 키(자연키, 대리키, 복합키), 관계(1:N, 1:1, M:N)의 이해와 설계, 식별/비식별 관계의 장단점 비교, 정규화(1NF, 2NF, 3NF, BCNF)를 통한 데이터 이상 현상 해결.
-   **물리적 모델링**: 테이블/컬럼 변환 규칙, 데이터 타입(문자열, 숫자, PK, 날짜/시간) 선정, 역정규화(성능 최적화), 테이블 정의서 작성.

## 2. 개발자에게 하고 싶은 이야기

-   **데이터베이스의 중요성**: 실무에서 발생하는 장애의 대부분은 데이터베이스를 잘못 다루어 발생하며, 백엔드 개발 역량의 상당 부분을 차지함. 깊이 있는 이해는 핵심 성장 비결.
-   **좋은 개발자로 가는 길**: 좋은 애플리케이션은 좋은 데이터베이스 설계에서 시작함. 설계 능력은 프로젝트를 주도하고 시니어로 성장하는 필수 역량임.
-   **넓은 시야의 중요성**: 다양한 도구를 다루고, 데이터베이스뿐만 아니라 애플리케이션까지 큰 관점에서 문제를 균형 있게 해결하는 능력이 필요함.
-   **비즈니스의 중요성**: 아무리 좋은 설계라도 비즈니스 요구사항을 제대로 이해하지 못하면 의미 없음. 개발자는 비즈니스 중심의 넓은 시야를 가져야 함. 설계 시점의 1시간은 개발, 운영 시점의 10배, 100배의 가치를 가짐.
-   **개발 인생 전반의 이야기**: 인터뷰 영상, 개발 경험 공유, 취업 및 이직 관련 조언 등 개발자로서의 성장을 위한 다양한 자료를 제공함.
