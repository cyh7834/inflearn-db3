# 10. 정규화

## 1. 정규화의 필요성: 데이터 이상(Anomaly) 현상

하나의 거대한 테이블에 모든 데이터를 저장하는 경우 다음의 심각한 문제 발생 가능.
- **갱신 이상 (Update Anomaly)**: 중복 데이터의 다중 수정 필요, 누락 시 데이터 불일치 발생 우려.
- **삽입 이상 (Insertion Anomaly)**: 특정 정보 삽입을 위해 불필요한 다른 정보 강제됨.
- **삭제 이상 (Deletion Anomaly)**: 특정 정보 삭제 시 필요한 다른 정보까지 손실될 수 있음.

## 2. 함수 종속성 (Functional Dependency)

- **정의**: 테이블 내 컬럼 값들이 다른 컬럼 값을 유일하게 결정하는 관계(X → Y). X를 결정자(Determinant), Y를 종속자(Dependent)라 함.
- **활용**: 정규화는 함수 종속성 관계 분석을 통해 잘못된 종속 관계를 파악하고 테이블을 분리하여 올바른 종속 관계로 재구성하는 과정임.

## 3. 정규형의 단계

### 제1 정규형 (1NF)

- **정의**: 테이블의 모든 컬럼이 원자적(Atomic) 값만을 가짐. (더 이상 분해할 수 없는 값)
- **문제점**: 복합 정보를 쉼표 등으로 구분 저장하는 방식은 데이터 검색, 수정, 타입 활용에 어려움이 있음.
- **해결**: 각 정보를 별도의 행으로 분리하여 1NF 만족.

### 제2 정규형 (2NF)

- **정의**: 1NF를 만족하고, 모든 컬럼이 기본 키에 대해 완전 함수 종속(Fully Functional Dependent)이어야 함. 즉, 부분 함수 종속(Partial Functional Dependency)이 없어야 함.
  - **부분 함수 종속**: 기본 키의 일부에만 종속되는 컬럼이 존재하는 경우. 데이터 중복 및 이상 현상 야기.
- **해결**: 부분 함수 종속 제거를 위해 종속 관계에 따라 테이블 분리.
  - `order_id`에만 종속되는 컬럼들은 `orders` 테이블로.
  - `product_id`에만 종속되는 컬럼들은 `product` 테이블로.
  - `(order_id, product_id)` 전체에 종속되는 컬럼들은 `order_item` 테이블로.

  ### 제3 정규형 (3NF)

- **정의**: 2NF를 만족하고, 이행적 함수 종속(Transitive Functional Dependency)이 없어야 함.
  - **이행적 함수 종속**: 기본 키가 아닌 컬럼이 다른 컬럼을 결정하는 관계(PK → 일반컬럼1 → 일반컬럼2). 데이터 중복 및 이상 현상 야기.
- **해결**: 이행적 함수 종속 제거를 위해 결정자(member_id)와 종속자(member_name)를 묶어 별도의 `member` 테이블로 분리.

### BCNF 정규형 (Boyce-Codd Normal Form)

- **정의**: 3NF보다 강화된 정규형으로, 테이블의 모든 결정자(Determinant)가 후보 키(Candidate Key)여야 함.
- **필요성**: 여러 후보 키가 존재하고 그 후보 키들이 서로의 일부를 포함하는 복잡한 관계에서 발생하는 데이터 이상 현상 해결에 필요.
- **해결**: 문제가 되는 함수 종속성을 기준으로 테이블 분리하여 BCNF 만족.
