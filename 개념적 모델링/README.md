# 3. 개념적 모델링 --- 요약

## 1. 요구 사항 분석과 핵심 요소 식별

-   개념적 모델링은 시스템이 반영해야 할 현실 세계의 비즈니스를 그림으로
    표현해 이해를 맞추는 단계.
-   요구 사항에서 **명사 → 엔티티/속성**, **동사 → 관계**로 도출.
-   쇼핑몰 요구 사항 분석 결과 주요 엔티티: **회원, 상품, 주문**.

## 2. 엔티티란?

-   데이터를 저장·관리해야 할 유무형의 대상.
-   엑셀 시트와 유사한 개념(시트 = 엔티티, 열 = 속성, 행 = 인스턴스).
-   엔티티의 특징: 업무 관련성, 식별 가능성, 여러 속성 보유, 인스턴스의
    집합, 다른 엔티티와 관계.

## 3. 엔티티 분류1 --- 존재 형태 / 역할 기반 분류

### 존재 형태

-   **유형 엔티티**: 사람, 사물 등 물리적 대상(회원, 상품).
-   **개념 엔티티**: 계좌, 학과 등 개념적 대상.
-   **사건 엔티티**: 주문, 결제 등 시점 기반 행위 기록. (가장 증가량이
    큼)

### 역할 및 발생 시점

-   **기본 엔티티**: 독립 존재(회원, 상품).
-   **중심 엔티티**: 기본 엔티티 간 관계에서 발생(주문).
-   **행위 엔티티**: 상세 이벤트 기록(주문 이력, 결제 내역).

## 4. 엔티티 분류2 --- 강한 엔티티 / 약한 엔티티

-   **강한 엔티티**: 독립적으로 존재(회원, 상품).
-   **약한 엔티티**: 부모 엔티티 없이는 존재할 수 없음(부양가족 등).
-   고아 데이터 방지, PK·FK 설계 시 중요.

## 5. 속성과 식별자

-   속성(Attribute)은 엔티티의 구체 정보.
-   식별자(Identifier)는 유일한 인스턴스를 구분하는 핵심 속성(PK).
-   예: 회원아이디, 상품코드, 주문번호.

## 6. 카디널리티와 참여도

-   **카디널리티(Cardinality)**: 관계 수량(1:1, 1:N, N:1, M:N).
-   **참여도(Optionality)**: 필수(M)인지 선택(O)인지.
-   예: 회원 -- 주문 관계: 회원(O\<)-주문(\|\|)

## 7. ERD 완성

-   엔티티, 속성, 관계, 식별자, 카디널리티, 참여도를 종합한 설계도.
-   실무에서는 **까마귀발(Crow's Foot)** 표기법 사용.
